# KeymasterMarketProtocol v1

## 读取目录

客户端对配置的完整目录 URL 发送无凭据的 `GET`。默认市场目录为 `https://market.bsv8.com/v1/apps`。第三方可使用任何路径，也可直接托管静态 JSON。生产使用 HTTPS。本机开发按宿主已有的 dev 配置接入。

成功响应为 `200 OK` 和 UTF-8 `application/json`。公开目录允许浏览器以无凭据方式跨域读取，参考实现对目录 GET 返回 `Access-Control-Allow-Origin: *`。请求不携带钱包身份、网络、历史、收藏或会话。

```json
{
  "apps": [
    {
      "url": { "publication": "<URL 渠道签名发布证明>" },
      "files": {
        "publication": "<Files 渠道签名发布证明>",
        "indexseedhashhex": "<完整已签名入口的 64 位小写十六进制种子摘要>"
      }
    }
  ]
}
```

- `apps` 必填，为市场当前完整清单。`{"apps":[]}` 是有效空目录。v1 无分页、增量或按钱包筛选。
- 每项至少有一个渠道，每个渠道最多一项。字段缺席表示该发布没有由此目录提供的对应渠道。客户端按原有发布证明格式解码、校验规范字节和签名，再读出公钥、`appVersion`、展示字段及对应渠道。目录不另传同义的公钥、版本、展示资料或 origin。
- URL 渠道的证明必须包含受签名 URL 渠道，入口是其中签署的完整 URL，包括路径、查询和片段。Files 渠道的证明必须包含受签名 Files 渠道。同一条目有两个渠道时，各自验签，公钥和版本必须一致；两个证明允许不同。发布证明内的其他渠道仅在目录也提供对应渠道对象时生效。
- Files 的 `indexseedhashhex` 是完整入口的定位值。它与证明里签署的、移除证明记录后的入口摘要不同。目录读取阶段仅校验定位值格式和发布签名。实际下载部署时必须验证返回的完整入口与请求摘要相符、入口证明与目录 Files 证明一致，并走现有入口和文件清单验证流程。签名目录不承诺文件可下载。
- 同一响应中，按验签得到的 App 公钥去重。重复公钥、缺字段、类型错误、无效渠道、签名失败、截断或解析失败使整份响应无效。只有完整通过校验的响应才能作为当前清单。消费者不按条目数组顺序决定生效。
- 协议负责目录传输与发布证明验证。市场接收作者提交、文件归档与分发、客户端的配置和同步状态、钱包归并和授权由各自产品定义。目录验签只证明发布内容归属。真实 URL 来源和 Files 部署的身份仍走现有可信入口验证。
